# Commercial Insurance (from Metabase): AtScale SML model

Generated by the `atscale-sml-model-generator` skill from the business catalog exported from Metabase
(database `Commercial Insurance`, collection `Commercial Insurance - Business Catalog`). Nothing else was
used: no other SML, only the Metabase export in `context/` and the skill's bundled references.

## Inputs

- `context/use_case.md`: tables, columns and 30 metrics with SQL-like definitions and business rules, exported from Metabase.
- `context/ddl.sql`: CREATE TABLE statements rebuilt from Metabase column metadata.
- `context/erd.mmd`: Mermaid ERD of the 10 foreign keys set in Metabase.
- `context/data_profile.yaml`: exact row, distinct and null counts computed through Metabase in Snowflake.
- `context/catalog.json`: the raw Metabase extract; used for column base types (integer vs decimal, Rule 22) and
  for the model relationships (each field's foreign-key target).
- `context/build.yaml`: build settings.
- NLQs: (not provided as a separate file; metric rules in use_case.md drive coverage).
- Target warehouse: Snowflake.

## Build parameters

- `unrelated_dimension_handling` = repeat
- `warehouse` = Snowflake (`as_connection: SnowflakePartner`)
- `model_unique_name` = commercial_insurance_metabase
- `catalog_unique_name` = commercial_insurance_metabase_catalog
- `database` / `schema` = SE_DEMO_LIBRARY / COMMERCIAL_INSURANCE
- `currency` = USD
- `time_window` = calendar (fiscal year = calendar year per the use case)
- `use_cases_covered` = all 30 Metabase metrics
- `use_cases_excluded` = none
- `semi_additive_default` = last_non_empty (the three "Balance" metrics)

## Assumptions and decisions

- **as_connection = SnowflakePartner**: the AtScale connection on demo2 that reaches SE_DEMO_LIBRARY (build prompt).
- **Column types from Metabase base types**: `NUMBER` reported as type/BigInteger -> `long`; `NUMBER` reported as
  type/Number (has a scale) -> `decimal`, never `double` (Rule 22). The exported DDL carries no precision.
- **Current-valuation loss metrics**: the catalog defines them as `SUM(x) WHERE CURRENT_VALUATION_IN = 'Y'`. SML metrics
  have no filter, so each is a calculated column `IFF(CURRENT_VALUATION_IN = 'Y', x, 0)` summed (fully additive).
- **Balance metrics are semi-additive** (`position: last`, `sum`) on the Snapshot date relationship, per the catalog rule
  "take the latest snapshot in the period, never add across snapshots".
- **Policies Written** = calculated column `IFF(GROSS_WRITTEN_PREMIUM_AMT > 0, 1, 0)` summed (catalog: COUNT WHERE GWP > 0).
- **Policies in Force** = `count distinct` of DIM_POLICY_ID (catalog: COUNT(DISTINCT DIM_POLICY_ID)).
- **Ratios use `Divide()`** over base totals, so ratios are computed from totals and blank (not infinite) on a zero
  denominator (e.g. premium ratios sliced by Claim, which only loss rows carry).
- **Combined / Operating Ratio** are sums/differences of the component ratio calcs, as the catalog defines them.
- **Relationships from Metabase foreign keys**: every TFACT_KPI field with a foreign-key target in `catalog.json`
  becomes a relationship to the dimension level keyed on that target column; a key with no matching level stops the build.
- **Date roles**: three fact keys point at TDIM_DATE, so one Date Dimension is role-played (Rule 21). Each role is
  named from the key's Metabase display name minus 'Date' / 'Month End': Snapshot, Fiscal and Accident.
- **Date hierarchy keys**: YEAR_NO, QUARTER_NO and MONTH_YEAR_NO are text, so numeric calculated keys YEAR_NUM,
  QUARTER_KEY and MONTH_KEY back the levels, with year-qualified labels YEAR_QUARTER_NM / YEAR_MONTH_NM as names.
  `parallel_periods` on Quarter, Month and Day are keyed on that level's own key one year earlier
  (PRIOR_YEAR_QUARTER_KEY, PRIOR_YEAR_MONTH_KEY, PRIOR_YEAR_DATE_ID), following the Internet Sales `*_lykey` columns.
  Rule 13's PRIOR_YEAR_NUM (a year key) matches no member below Year, so prior-year calcs return null there.
- **Prior year, YoY and YTD on the Fiscal role** (Rule 4: premium is booked by fiscal month): GWP, NWP, NEP get Prior Year
  and YoY Growth; GWP gets Year to Date, per the catalog's "report year-over-year and year-to-date on the fiscal calendar".
- **Product is a secondary attribute of Coverage**, not a level: the profile shows 11 products for 11 coverages (1:1).
- **Company Division is kept as a level** (single value, 'General Insurance') to match the catalog's hierarchy.
- **Catastrophe level keyed by name**; non-catastrophe claims fall under an empty Catastrophe member.
- **is_unique_key** set only where the profile's distinct count equals the row count (each dimension's ID key) (Rule 16).
- **Unused columns** (codes, denormalized keys, Policy Month Count) stay on the datasets but are not modeled; POLICY_COUNT
  counts policy-months per the catalog and is deliberately not exposed as a metric.
- **No company names in model metadata** (Rule 18): the carrier name appears only in warehouse data values.
- **Validator CASE check vs SnowflakePartner**: the bundled validator treats only `as_connection: Snowflake` as
  UPPERCASE storage, so it flags every identifier here. The data is in Snowflake (UPPERCASE); validating a copy with
  `as_connection: Snowflake` reports 0 issues, and `sml-cli validate` passes.

## Generation summary

- Datasets: 9 (8 dimension tables + TFACT_KPI)
- Dimensions: 8 (Date Dimension is `type: time`, role-played 3x)
- Base metrics: 18 (3 semi-additive Balance metrics; the rest additive or count distinct)
- Calculated metrics: 19 (ratios, results, prior year / YoY / YTD)
- Model relationships: 10 (3 role-played Date + 7 dimensions), all from Metabase foreign keys
- Role-play prefixes: Snapshot, Fiscal, Accident
- Snowflake bridges: none (every dimension is one table)
- Calculated columns: TDIM_DATE (YEAR_NUM, QUARTER_KEY, MONTH_KEY, PRIOR_YEAR_QUARTER_KEY,
  PRIOR_YEAR_MONTH_KEY, PRIOR_YEAR_DATE_ID); TFACT_KPI (4 current-valuation
  amounts, POLICY_WRITTEN_CNT)
- Caveats: Balance metrics fall back to a sum across snapshots when no Snapshot date level is in the query; premium
  measures sliced by Claim are empty (premium rows carry no claim); complete years are 2024 and 2025.

## Reproducing this build

`context/` holds verbatim copies of every input, including `build.yaml` and the raw Metabase extract. Re-running
`emit_sml.py` (or the skill) with the same Metabase export produces an equivalent model.
